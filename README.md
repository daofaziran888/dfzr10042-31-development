# 洞察工坊 · 多维交互分析与实验度量平台

面向数据分析师的多维下钻分析、指标口径管理、A/B实验评估、群体圈选分群、归因分析与数据看板构建的交互分析平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/WorkbenchView.vue|tsx  全部模块共享工作台
│   ├── src/data/modules.ts              24个业务模块配置
│   ├── src/api/              统一请求封装
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/resource.py  通用查询/导出/登记/动作接口
│   ├── app/services/<key>.py    每个模块独立领域逻辑
│   ├── app/services/base.py     共享服务骨架
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm ci
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 连续异常补审规则

采购指标序列按**有效日**计算费用补审资格，规则实现集中在
`backend/app/reaudit.py`，由 `procurement_audit`（补审清单）和
`expense_report`（费用报告）两个模块及
`pipeline_reaudit_to_expense_report` 管道消费。

- 实际观测按有效日排序；同一日重复提交只保留最后一份有效观测，其余记入
  `superseded`，不参与检测和金额聚合。
- 用 Z 分数 `abs(z) > 阈值`（默认 1.0）判异常；少于 4 个观测点不做判定。
- 连续异常按自然日相邻判定，两个异常日相差必须恰好 1 天；中间缺一天即断开。
- 只有连续异常天数 `>= 2` 的日期组才获得补审资格，孤立异常日不计入报告。
- 费用报告按补审清单的合格日期关联原采购记录，再用指标聚合（默认 `SUM`）算金额。
- 报告绑定实际采用的观察批次快照，后续提交不会改写既有报告，可随时按该批次重算。
- 复核员领走日账后、签发前登记的财务更正属于「计入财务更正」批次；若报告仍按
  领走的日账出单，则不采用该更正。同一报告并发确认只产生一次签发结果。

示例（`backend/app/seed.py`）：十天序列前八天各 10 元、第九天 100 元、第十天 10 元。

- 按领走日账出单：异常日期只有 09-09，孤立异常，补审金额 `0`。
- 计入末日财务更正（末日 100 元）：09-09 与 09-10 相邻且都异常，补审金额 `200`。

## 约定

- 全部模块共享`frontend/src/views/WorkbenchView.vue|tsx`和一套资源路由。
- 每个模块仍保留独立`backend/app/services/<模块>.py`；纯前端保留
  `frontend/src/domain/<模块>.ts`，用于承载真实业务差异并维持36题位容量。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
